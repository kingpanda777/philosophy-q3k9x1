## 作問と追記の道具を毎回書き直さない（`tools/add_batch.js`）

**点検のたびに `apply2.js` / `apply2b.js` / `apply3.js` / `measure.js` / `progress.js` を
scratchpad へ書き直していた。**同じ道具を4回書き直し、**そのたびに違う失敗をした。**
2026年9月17日に `tools/add_batch.js` へまとめ、リポジトリに据え付けた。
`progress.js` も `tools/progress_table.js` として据え付けた。

**対象フィールドを増やす・変えるときは、そのフィールドを直接参照している箇所を
`grep` で全部洗ってから直す。**

**理由。**2026年9月18日（`b89a515`）に追記へ `対象`（detail／explanation）を足したとき、
`applyAppends` だけを直して**書き込み前の事前検査 `auditKeyForms` を直し忘れた。**
explanation への追記9件がすべて「追記先の detail に find が無い」で止まっている。
**同じフィールドを2か所で見ていた。**dry-run が書き込みの前に止めたので実害は無かったが、
**片側だけ直すと、次は書き込みの途中で止まりうる。**

**失効条件。**フィールドの参照を一か所にまとめたとき。

**CLAUDE.md の文面を変えるときは、先に `tools/` をその文面で `grep` すること。**
規則は CLAUDE.md「作業の前に」の節にある。

## 使い方

```
node tools/add_batch.js <入力.json>            適用して検査まで走る
node tools/add_batch.js <入力.json> --dry-run  適用・検査したあと必ず差し戻す
```

**入力は1つの JSON にまとめる。**作問と追記と鍵語を別ファイルに分けない。

```json
{
  "作問": [ { "id":"q654", "philosophers":["リオタール"], "terms":["差異","言語"],
              "keys":["フィギュール"], "question":"…", "choices":["…","…","…","…"],
              "answer": 1, "explanation":"…", "detail":"…\n\n…\n\n…",
              "note":"…", "refs":["…"] } ],
  "追記": [ { "id":"q330", "find":"本文にある一文", "replace":"その一文＋足す文",
              "note_add":"追記の記録: …", "keys_add":["技術科学","非人間"] } ],
  "鍵語": {
    "作問由来": { "リオタール": [ {"語":"フィギュール","読み":"ふぃぎゅーる","追加":"…"} ] },
    "追記由来": { "リオタール": [ {"語":"技術科学","読み":"ぎじゅつかがく","追加":"…"} ] }
  }
}
```

**走る順序。どこかで落ちたら6ファイルを丸ごと元に戻して終了コード1で止まる**
（`questions.js` `keyterms.json` `index.html` `philosophers.js` `CLAUDE.md` `tools/keys_draft.json`）。

| 段 | 中身 |
|---|---|
| 0 | **入力の形を検査する。**1問も書かずに止まる |
| 1 | **鍵語の語形が本文に出るかを総点検する。**作問由来は草稿の本文、追記由来は追記後の本文で見る |
| 1.5 | **書き込みの前の検査7種。**keys 全部の語形・選択肢の長さ（「両者とも」型の下限を含む）・位置指し・detail の問題番号（作問と追記）・作問の detail の字数と段落数・`type` の指定・**作問の note の問題番号（存在しない問題を指していたら止める。人物の重ならない問題は △ を付けて一覧に出すだけ。2026年9月22日に足した）**。**2026年9月21日に規則と突き合わせて広げた。一覧は CLAUDE.md「入力の検査を規則と突き合わせた」の表。****`keys除去`・`refs追加`・`refs除去`・`refs置換` があるときは、それぞれの検査も走る。`type` の検査以外は作問に「許可」欄（理由）を書けば通る。`type` の検査だけは許可欄が無い**（2026年9月21日に足した） |
| 2 | `questions.js` へ作問を追記 |
| 3 | detail 追記。**字数は書き込んだあとに実測し、note へ道具が書く** |
| 3.5 | **`keys` から語を外す**（`keys除去`）。**語がどこにも残らなくなる／その問題の `keys` が空になる場合は止める**（2026年9月21日に足した） |
| 3.6 | **`refs` を足す・外す・差し替える**（`refs追加`／`refs除去`／`refs置換`）。**外して `refs` が空になる場合と、同じ URL を二重に足す場合は止める**（2026年9月21日に足した） |
| 4 | `keyterms.json` / `tools/keys_draft.json` / KEY_YOMI へ鍵語を登録 |
| 5 | `tools/gen_key_owner.js` で KEY_OWNER を再生成 |
| 6 | `node --check` → `check_keys` → `check_phil` → `coverage` → `tools/progress_table.js` |

**`coverage.js` は合否を終了コードで返さない。**数字を出すだけの道具なので、
**実行はするが落ちたかどうかは見ない**（node 自体の実行エラーだけ拾う）。

## 台帳モードを足した（2026年9月17日）

**点検の結果を台帳へ書き戻す作業も、毎回スクリプトを書き直していた。**
`fix.js` から `fix5.js`、`ledger6.js` まで6本。**そして書き直すたびに違う失敗をした。**
「十九世紀の反逆」の整備で**4回続けて止まった**ので、`tools/add_batch.js` へ吸収した。

```json
{
  "台帳": {
    "対象": ["人物", …],
    "刻印": "いつ何で判定したか",
    "扱い": {
      "主題": { "人物": ["語", …] },
      "理由": { "語": "なぜそう判じたか" }
    },
    "ずれの記録": { "語": "数えすぎ／数え漏らしの型" },
    "改名": { "人物": [ {"旧":"…","新":"…","読み":"…","理由":"…"} ] },
    "新規登録": { "人物": [ {"語":"…","読み":"…","付ける先":["qNNN"],"追加":"…"} ] }
  }
}
```

**台帳は作問・追記より先に走る。**改名で語形が変わると数え直しの対象も変わるためで、
**改名 → 扱いと数値 → 新規登録**の順に処理する。
**"作問" と "追記" を空にすれば、台帳だけを整えることもできる。**
**hits／全問は入力に書かない。**道具が本文を数えて実測を入れる。

**台帳モードには3つの操作がある**（2026年9月17日に足した）。
**「扱いの変更」**（旧の値を確かめてから書き換える）、
**「keysから外す」**（`q.keys`・`keys_draft` と、指定があれば台帳・`KEY_YOMI`・削除記録まで揃えて外す）、
改名の検査に**「部分文字列の残留を許す」**。

**先頭が重なる改名は、新語形を取り除いてから旧語形を探す。**
「通約不可能 → 通約不可能性」は旧語形が新語形の先頭部分なので、
**新語形が本文にある限り必ず残留と出る。**
**逃がし弁（`部分文字列の残留を許す`）は、別の語にたまたま旧語形が含まれる本来の型のために残してある。**

**鍵語を準備分として先に台帳へ登録した場合、入力の「鍵語」欄は使えない**（「既に台帳にある」で止まる）。
**そのときは `KEY_YOMI` への読みの追加を手で行う**
（`check_keys` の項目3が `q.keys` に出る語すべてに読みを要求するため）。

| **③ 正規表現に開き引用符が無い** | ②を直したら index.html が壊れ、check_keys が**例外で落ちた**（検査に落ちたのではない） | **開き引用符まで含めて拾う。**`\s*語":"…"` と書くと元の `"` が残り `"  "語"` になる。**KEY_YOMI は check_keys が評価するので、壊すと検査が動かない** |

CLAUDE.md には「鍵語は4か所に散在する」と既に書いてあり、**読んでいれば②は起きなかった。**
**道具にしたのは、次に同じ数え落としをしても機械が止めてくれるようにするためである。**

## 据え付けたときの確認（台帳モード）

**コミット `c583191`（台帳整備の直前）まで巻き戻し、今回の整備をそのまま入力にして
`--dry-run` を走らせた。**

- **扱い26語・数値11語・改名1語・新規登録18語**で、`5283924` の結果と**一致**した
- 未登場掃きも同じ1件（アウグスティヌス／三位一体）
- 到達点も**666問・台帳758語**で一致
- `check_keys` `check_phil` を含む検査5種が通り、**6ファイルが元に戻った**

**確認のあとリポジトリは HEAD へ戻した。**台帳は手で整えた版をそのまま残している。

**【失効】新規人物の初回は、作問と台帳モードを別実行にする（2026年9月18日。2026年9月20日に失効）。**
台帳モードは作問より先に走るので、同じ入力に入れると**扱いを主題にする時点でまだ問題が無く、`hits` が 0 のまま記録される。**
これは「非宗教的キリスト教」で直したのと同じ型の食い違いを、その場で作ることになる。
**作問を先に本番実行し、そのあと台帳モードだけをもう一度走らせて `hits` を実測させること。**
鍵語を準備分として先に登録してある場合、入力の「鍵語」欄は使えない（「既に台帳にある」で止まる）。
そのため **`KEY_YOMI` への読みの追加は手で行う**（`check_keys` の項目3が `q.keys` に出る語すべてに読みを要求する）。

**失効の理由（2026年9月20日）。**別実行にしたのは `hits` が0のまま記録されるのを避けるためだったが、
**`hits` と問題数の実測はどのモードでも末尾で必ず走る**ようになった（下の項）ので、別実行の理由は無くなった。
さらに**新規人物ではこの順では通らない。**台帳に人物エントリが無いと、
入力の「鍵語」欄も `台帳.新規登録` も「台帳にその人物がいない」で止まる。
作問だけを先に流した場合は **`check_keys` が2件落ちる**
（①台帳に無い語が `q.keys` に入る ②その語に読みが無い）。**シジウィックの登録で実測した。**

**新規人物の初回は、登録4か所を先に作ってから、作問バッチを1回流す（2026年9月20日）。**

| 何を | どこへ |
|---|---|

| 紹介の欄 | `philosophers.js` の `PHIL_INTRO` |
| 生没年の引用行 | `tools/years_src.json` |
| 台帳の人物エントリ（鍵語は空） | `keyterms.json` |

**`node tools/add_person.js tools/_people/<名前>.json` が4か所をまとめて作る。**そのあと作問バッチを流せば、
鍵語は入力の「鍵語」欄で登録でき、**台帳モードの別実行は要らない。**
（2026年9月21日に汎用化した。人物データは入力 JSON で渡す。詳しくは CLAUDE.md の
「人物を登録する道具（`tools/add_person.js`）」の節）

**理由。**道具は台帳の人物エントリを作らないので、器だけは先に手で用意する必要がある。
**この順でシジウィックを登録し、検査5種すべてが通ることをサンドボックスと本番の両方で確かめた（2026年9月20日）。**
**失効条件。**`add_batch.js` が台帳の人物エントリを自分で作るようになったとき。

**hits と問題数の実測は、どのモードでも末尾で必ず走る（2026年9月18日）。**
もとは台帳モードの中にあったので、**作問だけ・追記だけの実行では走らなかった。**
実際、位置指しの書き換えで q590 から一文が落ち、ロールズ「格差原理」の全問が
6から5へずれたまま push した（`6038b7e` で直した）。
**「本文を書き換えたら台帳モードも通す」という運用は人が忘れる。**
`refreshCounts()` として `applyLedger` の外へ出し、
**`registerKeys` の直後・検査の手前**で呼ぶようにした。
作問・追記・鍵語登録がすべて終わったあとの本文を数える必要があり、
`registerKeys` も `keyterms.json` を書くので、そのあとで読み直して上書きする。

**したがって台帳モードを別実行する理由は、扱いの設定と改名だけになった。**
数値を合わせるためだけに台帳モードを走らせる必要はない。

## 道具を書き直さないと決めた範囲

| 作業 | 道具 |
|---|---|
| 作問 | `tools/add_batch.js` の "作問" |
| detail 追記 | 同 "追記" |
| 鍵語の登録 | 同 "鍵語"（作問由来・追記由来を分ける） |
| **台帳の整備** | 同 **"台帳"** |
| 進捗表 | `tools/progress_table.js`（add_batch から呼ばれる） |

**scratchpad へ書き直してよいのは、点検の照合スクリプト（`match*.js`）だけである。**
あれは学派ごとに中心概念のリストが変わるので、使い捨てで構わない。
**書き込みに関わるものは、もう書き直さない。**
